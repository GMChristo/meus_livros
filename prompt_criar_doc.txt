# Documentação completa do projeto Flutter

Quero que você faça uma análise completa deste projeto Flutter e, com base exclusivamente no código e nos arquivos reais do projeto, crie ou atualize o arquivo:

`README.md`

O objetivo deste README é documentar detalhadamente como o projeto está estruturado, como ele funciona e quais padrões e decisões técnicas foram utilizados.

Esse documento deverá ser útil tanto para desenvolvedores humanos quanto para uma IA que futuramente precise entender, manter, corrigir ou desenvolver novas funcionalidades neste projeto.

# 1. Regra principal: primeiro investigar, depois documentar

**Não comece escrevendo o README imediatamente.**

Primeiro analise o projeto.

Você deve explorar a estrutura de diretórios e arquivos e entender como as diferentes partes do sistema se relacionam.

A documentação deve representar a implementação **real e atual** do projeto.

Não assuma que o projeto utiliza uma arquitetura apenas porque ela é comum em aplicações Flutter.

Por exemplo, não presuma que o projeto utiliza:

* Clean Architecture;
* MVVM;
* MVC;
* Bloc;
* Riverpod;
* Provider;
* GetX;
* Repository Pattern;
* qualquer outro padrão;

a menos que isso seja confirmado pelo código.

Se existir uma arquitetura própria ou uma combinação de padrões, documente o que realmente existe.
